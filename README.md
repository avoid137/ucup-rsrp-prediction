# UCup 2026 Summer Online Challenge — 基站 RSRP 信号强度预测

2026 Universal Cup Summer Online Challenge（华为赞助、深圳河套学院 SLAI 合作）赛题：
在复杂城市场景下，用基站工程参数 + 无人机点云 + 少量实测信号，预测**新部署基站**覆盖范围内
未知位置的 RSRP（Reference Signal Received Power，参考信号接收功率）。

本仓库是该赛题的**本人实现**：一条从点云到提交文件的四步流水线。

---

## 方法概览

核心思路是**用物理模型造数据，补实测样本的分布盲区，再用真实数据把模型拉回地面**。

实测样本虽有百万级，但只覆盖已建站的实际场景；纯数据驱动的模型学不到
「距离—损耗」「遮挡—衰减」这类物理规律，换到新基站上误差很大。所以先用简化的
射线追踪模拟器合成一批带标签样本做预训练，再在真实数据上用小学习率继续训练。

```
原始数据 (点云 .ply + 基站参数 ep.json + 实测信号 train_signal.csv)
    │
    ├─ 1. pointcloud_to_mesh.py      点云 → 3D 网格（Open3D 泊松重建）
    │
    ├─ 2. generate_simulation_data.py  物理仿真 → 合成样本 CSV
    │
    ├─ 3. two_stage_training.py      XGBoost 两阶段训练 + 误差分析
    │
    └─ 4. generate_submission.py     逐点预测 → output.zip

    features.py                     第 1~4 步共用的 17 维特征实现（唯一来源）

    smoke_test.py                   合成数据冒烟测试（不碰赛题数据，验证上面几条声称）
```

### 1. 点云转网格（`pointcloud_to_mesh.py`）

泊松重建把散乱点云变成封闭曲面，之后才能做「射线是否穿墙」的遮挡判定。

裁剪地面以下点 → 体素降采样（目标 30 万点）→ 估计法线 → 泊松重建（八叉树深度 8）
→ 按密度 5% 分位剪掉低置信度面片 → 清理退化/重复/非流形面。

地面高程不可得，用「天线挂高的 0.7 倍」与「点云 z 的 5% 分位」两个启发式量折中；
两者相差超过 20 m 时判定前者不成立，退回用数据自己的分位数。

### 2. 物理仿真造数据（`generate_simulation_data.py`）

在每个基站周围 500 m 内采样，逐点计算 RSRP：

| 项 | 做法 |
|---|---|
| 自由空间路径损耗 | Friis：`20·log10(d) + 20·log10(f) − 147.55`，f = 3.5 GHz |
| 遮挡损耗 | KDTree 空间索引，沿收发连线采样 30 点，距墙体 < 3 m 判为遮挡，附加 10–30 dB |
| 水平天线增益 | 主瓣内二次衰减（±30° 内），主瓣外线性衰减 |
| 多径增益 | LOS / NLOS 分别取不同随机分布 |
| 阴影衰落 | 高斯噪声 σ = 1.5 dB（简化处理） |

采样策略：距离用指数分布（λ=120）偏向近处，角度 60% 落在主瓣附近的正态分布、
40% 全向均匀。共生成 **18.8 万条**合成样本（94 个基站 × 2000 点）。

> 遮挡判定用 KDTree 把单次查询从 O(N) 降到 O(log N)，累计 564 万次查询在秒级完成。
> 每个基站的随机种子由 `crc32(cell_name)` 决定，与运行环境无关 —— 同一份代码重复运行
> 得到的仿真数据完全一致（不能用内置 `hash()`，它受 `PYTHONHASHSEED` 影响）。

### 3. 训练（`two_stage_training.py`）

**17 维特征**（定义见 `features.py`）：坐标、水平距离及其平方/对数/倒数、角度的三角函数、
天线挂高/方位角/下倾角、高度距离比、下倾角距离积、方位角差、天线增益、遮挡代理特征。

**阶段 1｜合成数据预训练**：正常学习率（0.05）在合成数据上训练，早停用留出的合成基站。

**阶段 2｜真实数据微调**：把阶段 1 的 `Booster` 通过 `xgb_model=` 传给阶段 2 的 `fit()`，
学习率降到 **0.01**，在真实数据上继续加树。

> 为什么必须显式传 `xgb_model`：xgboost 的 sklearn 接口重复调用 `fit()` 会**丢弃已有树、
> 从头重训**（官方文档明说）。不传 `xgb_model` 的"两阶段"其实是两次互不相干的独立训练，
> 阶段 1 的模型只贡献了一个对比数字，没有作为阶段 2 的起点。
> 本文件在训练结束后会**程序化校验**续训是否成立：dump 两个 Booster 的树序列，
> 确认阶段 1 的树构成阶段 2 树序列的前缀，不通过就直接报错退出。

**两阶段同源的三条约束**（否则阶段 1 学到的树在阶段 2 的特征空间里没有意义）：

1. 特征：共用 `features.py::engineer_features`，特征空间完全一致；
2. 标准化：共用同一个 scaler，且**只在合成数据的训练集上 fit**，真实数据的统计量从不参与；
3. 超参：阶段 2 只降学习率、追加轮数，`max_depth` / `subsample` / `colsample` 保持不变 ——
   微调用小学习率是为了在真实数据上做小幅修正，不把第一阶段学到的物理先验冲掉。

### 4. 生成提交（`generate_submission.py`）

直接 import 训练用的同一份 `engineer_features`（不是复制一份），
预测后裁剪到 −130 ~ −40 dBm 的物理范围，按基站输出 CSV 并打包。

> 特征漂移在这类比赛里是**无声的**：不报错，分数直接掉一半。最初版本把特征代码在
> 训练/推理两个文件里各写了一份，只要有一边改动就会漂移；抽成公共模块后这种错不可能发生。

## 数据划分：按基站分组，而不是随机划分

同一基站的采样点在空间上高度相关，随机划分会让训练集和验证/测试集共享基站，
指标虚高。赛题真正考察的是**新基站的泛化能力**，所以用
`GroupShuffleSplit(groups=cell_id)` 分组划分：**一个基站的全部采样点只落在
train / val / test 其中之一**。

真实数据按 60% / 20% / 20% 分成训练 / 早停 / 测试三份；**早停只看 val，
最终报出的 MAE 只在 test 上算一次**（test 全程不参与任何超参或轮数选择）。

## 结果

| 指标 | 数值 | 口径 |
|---|---|---|
| 仿真模型在仿真留出集上的 MAE | 2.07 dB | 本地自测（过拟合到自己的仿真器） |
| 仅合成数据训练的模型，在真实测试集上的 MAE | 27.88 dB | 本地自测 |
| 真实数据微调后的模型，在真实测试集上的 MAE | **6.66 dB** | 本地自测 |

27.88 dB 这个数字本身是有价值的：它**量化了 sim-to-real gap**——模型在自己理想化的
物理模型上 MAE 只有 2.07 dB，那是过拟合到了仿真器上，不是学到了真实信道。
这说明纯仿真预训练不足以替代实测数据，也正说明阶段 2 的存在是必要的。

> ⚠️ **口径说明（两条，都请务必看清）**
> 1. 以上均为**本人本地留出测试集自测**，不是赛事榜单分数。
> 2. 这些数字来自**整理前的运行记录**。本仓库代码在整理时修正了若干逻辑问题（见下节），
>    因此**不保证与上表逐位一致**，重跑请以你自己得到的结果为准。
>
> 本仓库不附带赛题数据（按参赛条款属保密信息），因此**结果不可直接复现**。

理论参照：城市宏小区阴影衰落 σ ≈ 4–12 dB（常用经验值 8 dB），这构成约 6 dB 量级的
平均误差下界。做到 6.66 dB 说明系统性的几何/遮挡规律基本被模型学到了，
剩余误差主要来自不可预测的随机阴影与测量噪声。

## 整理说明：上传版相对原始脚本改了什么

这个仓库不是把当时的脚本原样搬上来，而是逐行核过一遍之后整理过的版本。
下面每一处都是**逻辑问题**（会导致代码和结论对不上），不是格式调整：

| # | 问题 | 影响 | 修正 |
|---|---|---|---|
| 1 | 阶段 2 调用 `fit()` 时**没有传 `xgb_model`** | 所谓"预训练 + 微调"实际是两次独立训练，阶段 1 没接上 | 传 `xgb_model=stage1_booster` 实现真正的 training continuation，并加**树序列前缀校验**（不通过直接报错） |
| 2 | 早停写在 `fit()` 的 `try/except` 兜底里 | xgboost ≥ 2.0 把 `early_stopping_rounds` 移到了构造函数，`fit()` 上会抛 `TypeError`，于是**静默退化成不早停**，跑满全部轮数 | 运行前探测 `fit()` 签名，新版把早停配到构造函数，旧版才放 `fit()` |
| 3 | 用 `train_test_split` 随机划分 | 同一基站的采样点同时进训练和测试，指标偏乐观，与"考察新基站泛化"相矛盾 | 改用 `GroupShuffleSplit(groups=cell_id)` 三份划分 |
| 4 | `visualize_results` 在**全部真实数据**上算 MAE | 图上报的是训练+测试混合的指标，比留出测试集乐观 | 只传入留出的测试集 |
| 5 | 仿真表用 `is_blocked` 真值、实测表用距离代理当同一列 | 同名不同义，两个阶段的特征空间不一致，续训无从谈起 | 两个阶段统一用几何代理 `exp(-d/150)·0.5`；遮挡信息**通过标签**间接进入模型 |
| 6 | `distance` 列"已存在就沿用" | 仿真表里是含天线高度差的 3D 距离，实测表里是水平距离，同名不同义 | 一律从 x、y 现算水平距离（500 m / 30 m 挂高时两者差 0.16%，折算路损约 0.014 dB） |
| 7 | `angle` 在两张表里取值域不同 | 仿真采样角是 [0,360)，实测 `arctan2` 是 (-180,180]，同一方向两个值，树的分裂点错位 | 统一归一化到 [0, 360) |
| 8 | 特征代码在训练/推理两个文件里各有一份 | 特征漂移风险，且漂移后不报错、只是分数暴跌 | 抽成 `features.py`，两处 import 同一实现 |
| 9 | `np.random.seed(hash(cell_name))` | 字符串 `hash()` 受 `PYTHONHASHSEED` 影响，**每次运行生成的仿真数据都不同**，结果不可复现 | 改用 `zlib.crc32`，种子确定 |
| 10 | 按目录名前缀（`cell_0` / `cell_1`）区分训练/测试基站 | 编号到三位数时 `cell_10x` 会被误判 | 改为按文件存在性判定（有 `train_signal.csv` = 训练基站，有 `test_points.csv` = 测试基站） |
| 11 | `pointcloud_to_mesh.py` 里有一个从未被调用的 OBJ 读取函数；多 PLY 时取 `glob()[0]` 顺序不定 | 死代码 + 不确定行为 | 删除死代码；PLY 列表排序后取第一个 |
| 12 | 硬编码的绝对路径 | 换机器不能跑 | 全部改为环境变量 + 仓库内相对路径 |

**这些修正都只做了静态与合成数据验证**（用小规模合成数据集把训练→推理全流程跑通，
校验了分组不重叠、续训前缀成立、早停生效、提交包生成），**没有在真实赛题数据上重跑**。

### 怎么自己核验这些声称

不用赛题数据也能验。`smoke_test.py` 会现造一份结构相同、内容全随机的假数据集，
跑完「训练 → 推理」全流程，然后**程序化断言**下面四条（不是靠注释声明）：

```bash
python smoke_test.py     # 期望 4/4 通过
```

| 检查项 | 断言的是什么 |
|---|---|
| 分组划分不跨基站 | train / val / test 三个集合的 `cell_id` **两两不相交** |
| 特征两阶段同源 | `engineer_features` 对"带干扰同名列的表"与"干净表"给出**完全一致**的特征值；`distance` 按 x、y 现算；`angle` 落在 `[0,360)` |
| 阶段 2 是真续训 | 阶段 1 的树序列是阶段 2 树序列的**前缀**（`xgb_model` 真生效，不是重训） |
| 早停生效 | 阶段 1 保留的树数 **< n_estimators**（否则说明早停被静默关掉了） |
| 提交包结构 | `output.zip` 生成、每个测试基站一个 CSV、列名正确 |

> 它验证的是**逻辑**，不是成绩——假数据上的 MAE 没有任何意义，测试里也不做断言。

## 已知局限

- **不提供可复现的成绩结论**：见上方两条口径说明。要成绩请自行重跑。
- **物理模型是简化版**：阴影衰落只用高斯噪声（σ=1.5 dB），未用城市宏小区常见的对数正态
  σ=4–12 dB；多径只用随机增益，未建模瑞利/莱斯分布；天线方向图只考虑水平面，
  缺少垂直面下倾角方向图；未建模高度增益与地形起伏。这些简化正是 27.88 dB 的来源。
- **仿真与实测的遮挡表征不对等**：仿真是逐点射线判定（真值），实测只能给几何代理，
  信息量本身不同 —— 这是两阶段迁移的固有难点，不是实现能完全补上的。
- **未做交易成本之类的下游约束**：本项目只到预测误差为止，没有把 RSRP 转成覆盖/容量指标。
- **地面高程是启发式估计**，点云不以绝对海拔表达，重建网格在 z 方向有系统性偏差的可能。
- **训练数据依赖赛事方提供的数据集**，本仓库不含数据，无法端到端复现。

## 环境与运行

```bash
pip install -r requirements.txt

# 0. 可选：不需要赛题数据，先确认代码逻辑没问题
python smoke_test.py

export UCUP_DATA_ROOT=/path/to/TrainingData.26UCupSummer
export UCUP_MESH_DIR=/path/to/TrainingData_Meshes_v2

python pointcloud_to_mesh.py       # 1. 点云 → 网格
python generate_simulation_data.py # 2. 物理仿真 → simulation_data.csv
python two_stage_training.py       # 3. 两阶段训练
python generate_submission.py      # 4. 生成 output.zip
```

Windows CMD（把 `export` 换成 `set`）：

```cmd
set UCUP_DATA_ROOT=D:\path\to\TrainingData.26UCupSummer
set UCUP_MESH_DIR=D:\path\to\TrainingData_Meshes_v2
```

可覆盖的环境变量：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `UCUP_DATA_ROOT` | `data/TrainingData.26UCupSummer` | 赛题数据根目录 |
| `UCUP_MESH_DIR` | `data/TrainingData_Meshes_v2` | 重建网格输出/读取目录 |
| `UCUP_OUTPUT_DIR` | `outputs/simulation_data` | 仿真样本输出目录 |
| `UCUP_SIM_DATA` | `outputs/simulation_data/simulation_data.csv` | 训练脚本读取的合成数据 |
| `UCUP_OUTPUT_DIR_2S` | `outputs/two_stage_results` | 模型与图表输出目录 |
| `UCUP_MODEL_PATH` | `outputs/two_stage_results/two_stage_model.pkl` | 推理脚本加载的模型 |
| `UCUP_SUBMISSION_DIR` | `outputs/submission` | 提交包输出目录 |

依赖：见 `requirements.txt`。训练环境为 Python 3.10 生态（CPU / 16 GB 内存，XGBoost 两阶段
约 30 分钟量级）。
